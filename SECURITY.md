# Security policy

## Supported versions

| Version | Security fixes |
| --- | --- |
| `0.1.x` | Supported after the first public tag |
| Development branches | Best effort; reproduce against the release branch |

## Report a vulnerability

Use GitHub private vulnerability reporting or a private security advisory for
the repository. Do not open a public issue with exploit details, credentials,
robot network information, or unsafe reproduction steps.

Include the affected commit/version, component, impact, prerequisites, and the
smallest safe reproduction. Maintainers will acknowledge the report, assess
severity, coordinate a fix and disclosure, and credit the reporter if desired.

Security reports cover software vulnerabilities. Robot behavior, controller
tuning, and physical safety validation must also follow the operator's hardware
and facility procedures; a simulation result is not a hardware safety
certification.
